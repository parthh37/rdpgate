Open source · Windows server · Mac & Windows clients · no static IP

Port 3389 stays closed.
Until it's you.

RDP Gate keeps Remote Desktop invisible to the internet. Sign in from your own computer with its device key and a 6-digit code, and Windows Firewall opens for your IP address only. When you disconnect, it closes again. No static IP, no DNS name, no VPN.

What it looks like

Two small windows. One on the PC you connect to, one on each computer you connect from. Screenshots use sample data.

The app on your Mac or PC: set up once, then sign in

  1. Create a key. It's made on this computer and encrypted with your passphrase.

  2. Enroll it. Copy one line to the server and paste back the server card.

  3. Sign in. Your passphrase and a 6-digit code from your phone.

  4. You're in. Open for your IP only, with the Remote Desktop certificate checked.

Managing the server: no command line needed

How it works

  1. Remote Desktop starts closed

    The installer sets Windows Firewall to block everything inbound and disables the built-in Remote Desktop rules. Only the RDP Gate sign-in service listens, on HTTPS.

  2. The app finds your PC and checks it's really yours

    It reads your PC's current address from an encrypted, signed beacon, connects directly, and makes the server prove its identity key before saying a word. Then it signs in with this computer's private key and your 6-digit code.

  3. The firewall opens for your IP only

    RDP Gate adds one allow rule for your current public address. The app checks the Remote Desktop certificate before opening it. Access stays while you're connected and closes a few minutes after you leave, or after 12 hours at most.

Two ways to sign in

From your Mac or PC

RDP Gate app or the rdpgate command

  • A private key created on this computer, encrypted with your passphrase (Argon2id + XChaCha20-Poly1305)
  • A 6-digit code from any authenticator app, each code usable once
  • Remote Desktop opens automatically when you're in

From a browser (optional)

With your own domain name

  • A passkey: Touch ID, Face ID, Windows Hello or a hardware key
  • The page shows which IP was opened and the certificate to expect
  • Browsers bind passkeys to a name, so this one needs a domain

What stands between the internet and your desktop

From the outside in. An attacker has to get through every one.

Hidden
Port 3389 is closed. The sign-in port only answers the RDP Gate protocol, limits each source, and goes silent for sources that keep failing.
Server proves itself
Your app pinned the server's identity key. A fake server, a hijacked address or a forged beacon is caught before the app sends anything.
Enrolled device
Every request is signed with an Ed25519 key you enrolled on the server, bound to that TLS 1.3 connection, so it can't be replayed or relayed.
Second factor
A one-time 6-digit code (10 wrong ones lock that computer), or a passkey that requires your fingerprint, face or PIN.
One public address, for a while
The allow rule names your public IP alone and expires on its own. Leftover rules are swept at every start.
Windows itself
Network Level Authentication, TLS, your Windows password and an account lockout policy, all switched on by the installer.

Download

Windows Server RDP-Gate-Server-Setup-….exe: Setup wizard for the PC you connect to. Windows 10/11 Pro, Enterprise or Server. macOS 11+ Mac app RDP-Gate-…-macOS.dmg: drag RDP Gate to Applications. Intel and Apple silicon. Windows PC app RDP-Gate-Setup-….exe: installs just for you, with no administrator rights needed. Uses the built-in Remote Desktop Connection.

Builds aren't Apple- or Microsoft-signed yet. On a Mac, right-click the app and choose Open the first time. On Windows, at the SmartScreen prompt choose More info, then Run anyway. Check downloads against SHA256SUMS.txt on the release page. Portable zips are there too.

Updates install themselves, and only if they're genuine

Each release carries a manifest of every file's checksum, signed with the RDP Gate release key. Every program has the matching public key built in.

Server
Checks once a day and installs only while nobody has access open, then restarts itself. Run rdpgate-server update to update now.
Desktop app
Checks at launch, installs, and offers Restart now. Turn it off under This computer and server.
Command line
Updates after a successful rdpgate connect, once a day. Run rdpgate update to update now.
Refused
Anything unsigned, a file that doesn't match its signed checksum, and anything older than what's installed, whoever serves it.

Setup

About 15 minutes. You need a Windows 10/11 Pro, Enterprise or Education PC (or Windows Server), access to your router, and a GitHub account.

  1. Make a GitHub token for the beacon

    Use a free GitHub account just for RDP Gate: a Gists token can read and change every gist on its account. Create a fine-grained token with only Account permissions → Gists: Read and write. Your PC uses it to publish its encrypted, signed address.

  2. Run the server Setup

    On the Windows PC, run RDP-Gate-Server-Setup.exe and click through. A domain name is optional (only for browser sign-in). Setup hardens Remote Desktop, configures Windows Firewall and your router, then asks for the token. At the end, leave Set up 6-digit codes now ticked and scan the QR code with your authenticator app.

  3. Your firewall and router: usually nothing to do

    Setup configures Windows Firewall itself and forwards TCP 443 and 3389 on your router automatically (UPnP). It tells you if the router refuses, or if your ISP uses carrier-grade NAT. If you have to forward by hand, send both ports to this PC. Either way, give the PC a reserved address in the router. Port 3389 stays shut until someone signs in. The apps on your Mac or PC need no open ports.

  4. Install the app on each computer

    Windows: run RDP-Gate-Setup.exe. It installs just for you, with no administrator rights needed. Mac: open the .dmg and drag RDP Gate to Applications, then right-click it and choose Open the first time. On a Mac you also need Microsoft's free Windows App.

  5. Enroll the computer

    In the app, name the computer and choose a passphrase. It shows one command; run it on the server in PowerShell as Administrator. Check that the fingerprints match, then paste the server card the server prints back into the app.

    rdpgate-server device-add macbook rdpgate-ed25519:…
# → rdpgate-card:…   paste this into the app

  6. Connect

    Enter your passphrase and 6-digit code and choose Sign in and open Remote Desktop. The app finds your PC, checks it's really yours, checks the Remote Desktop certificate, and opens the session. Then log in to Windows as usual.

Want browser sign-in with a passkey as well? Give Setup a domain you own that points at your home IP, then run rdpgate-server passkey-enroll and open the link on your phone or Mac.

Honest limitations

  • Shared IP addresses. While access is open, anyone behind the same public IP (hotel Wi-Fi, office, mobile carrier NAT) can reach the Windows login screen. They still need your Windows password. Close access when you're done; tunnel mode on the roadmap removes this.
  • Not independently audited. RDP Gate is new. It builds on audited parts (rustls, RustCrypto, webauthn-rs) and passed an internal adversarial review, but has had no third-party audit.
  • Nothing is unbreakable. A compromised Windows PC or a stolen, unlocked laptop with your passphrase and phone defeats any gate. RDP Gate removes the internet-facing attack surface; it doesn't replace updates and good passwords.
  • Windows Home can't accept Remote Desktop connections at all.

Questions

Do I need a static IP address or a domain?

No. Your PC publishes its current address as an encrypted, signed beacon in a secret GitHub gist. The gist only ever holds ciphertext (GitHub, like any website, does see the IP address each update comes from), and nobody can forge a beacon without your server's key. A domain is only needed for the optional browser sign-in.

Why not just a VPN?

A VPN is a fine answer. RDP Gate is for people who want one small thing on the server, no always-on tunnel on every laptop, and a browser fallback with a passkey.

What happens if I lose my laptop?

Its key is useless without your passphrase and your second factor. Remove it anyway: rdpgate-server device-remove macbook takes effect immediately.

Does anything phone home?

No. The server asks two public "what is my IP" services and updates your own gist. With a domain, it also talks to Let's Encrypt. There is no telemetry and no account with us.

Could a fake update take over my computers?

Not without the release key. The programs refuse updates without a valid signature and refuse to go back to older versions. A compromised download, a network attacker, or someone who can only edit the release page can't get code onto your machines.

What if someone points my PC's address somewhere else?

The app refuses to talk to any server that can't prove your server's pinned key, and refuses to open Remote Desktop if the RDP certificate doesn't match what your server vouched for. Worst case, you can't connect; you never connect to the wrong machine.
